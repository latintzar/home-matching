## ✅ What Changed

### Old Format (REMOVED)
```json
{
  "photo_url": {
    "visible_cluster_ids": [2, 5],
    "visible_cluster_names": ["Living Room", "Dining Room"],
    "details": []
  }
}
```
- Used cluster IDs (required lookups)
- Hybrid format (IDs + names)
- Legacy from manual UI

### New Format (MAIN)
```json
{
  "visibility_mappings": [
    {
      "photo_url": "https://...",
      "cluster_name": "Kitchen",
      "visible_clusters": ["Living Room", "Dining Room"],
      "visibility_details": [
        {
          "cluster_name": "Living Room",
          "visible_from": "through doorway",
          "confidence": 0.9
        }
      ]
    }
  ],
  "cluster_adjacency": {
    "Kitchen": ["Living Room", "Dining Room"],
    "Living Room": ["Kitchen"]
  }
}
```
- Uses cluster names directly (no ID lookups)
- Rich metadata (how visible, confidence)
- Includes adjacency graph
- Generated by Stage 4, stored directly

## 📊 Format Comparison

| Aspect | Old Format | New Format |
|--------|-----------|------------|
| **Cluster References** | IDs (integers) | Names (strings) |
| **Lookups Required** | Yes (ID → name) | No (direct names) |
| **Metadata** | Basic | Rich (details, confidence) |
| **Adjacency** | Not included | Included (`cluster_adjacency`) |
| **Structure** | `{photo_url: {ids, names}}` | `{visibility_mappings: [...], cluster_adjacency: {...}}` |

## 🔄 Data Flow (Updated)

```
Stage 4 (Auto-Clustering)
  ↓
{visibility_mappings: [{photo_url, cluster_name, visible_clusters: [names], visibility_details}], cluster_adjacency: {...}}
  ↓
Promotion Endpoint (stores directly, no conversion)
  ↓
clusters.visibility_mappings (Stage 4 format)
  ↓
Normalization Function (extracts names directly)
  ↓
clusters_normalized.visibility_mappings_normalized
  ↓
{photo_url: {visible_rooms: [names]}}
  ↓
All Consumers (R pipeline, OMSRIA, analysis)
```

## ✅ Benefits

1. **No ID Lookups**: Direct cluster name access
2. **Rich Metadata**: Confidence scores, visibility details
3. **Adjacency Graph**: Built-in cluster adjacency mapping
4. **Consistent**: Same format from Stage 4 → Storage → Consumers
5. **Simpler**: Less conversion logic, fewer bugs
6. **Future-Proof**: Extensible structure
